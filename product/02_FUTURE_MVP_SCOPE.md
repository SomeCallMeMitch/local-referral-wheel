# Future MVP: challenge the need for an app

> Latest direction (2026-09-13): Vallejo, California and surrounding cities; founder role is connector; every fee/amount remains illustrative, with participating-business profitability first. See [current connector and fee-design update](../strategy/09_VALLEJO_CONNECTOR_AND_FEE_DESIGN.md). This update overrides conflicting earlier defaults.
The original 12-entity blueprint may be a future domain map. It is too large as a commitment before member behavior exists.

| Must track manually now | Worth building after validation | Probably unnecessary until scale |
|---|---|---|
| Provider scope/contact/capacity | Directory only if existing shared directory is inadequate | Multi-chapter administration |
| Consented intro/status/next action | Fast status update and reminder workflow if repeatedly used | Chapter billing hierarchy |
| Action owner/date | Commitments only if members actually follow them | Large meeting/asset/curriculum library |
| Dues and private evidence | Simple private value report if preparation is costly | Cross-business KPI integrations |
| E: jobs/collections/fee eligibility | Fee ledger/reconciliation for proven E | Referral graph visualization |
| C: experiment baseline/action/result | Experiment log only if C wins | Benchmark datasets and AI recommendation engine |

## Absolute minimum conditional MVP
If A validates: provider profile + referral record with status and next action. Generate reports from those records. A separate commitments module and dashboard are optional, not sacred. Existing billing handles dues. "Chapter" is not needed until multiple groups actually exist.

If E validates: relationship agreement metadata + provider profile + referral/job/payment ledger with corrections and auditability. Reconciliation and permissions matter more than a wheel graphic. Do not store legal agreements as casual editable profile fields.

If C validates: firm-specific work item, baseline, asset and outcome. There may be no referral product at all.

## Build gate
At least one completed paid pilot and >=75% paid renewal at stated continuing terms; repeated use of at least two core workflows for eight weeks; >=90% current status records; measured admin bottleneck >=5 hours/month or material handoff errors; clear evidence existing tools cannot solve it economically. These are proposed thresholds.

Compare total build + maintenance + migration + support cost against saved operator time and verified benefits. A 5-hour/month inconvenience alone does not justify custom software. No member login unless it reduces friction relative to replying to an email. If forms/email work, keep them.
